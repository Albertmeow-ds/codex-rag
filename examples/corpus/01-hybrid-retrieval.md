# Hybrid Retrieval

混合检索把稀疏检索与稠密检索组合起来，是当前生产级 RAG 的默认起点。BM25 依赖词面匹配，对专有名词、代码标识符、数字和罕见术语非常精准；稠密向量检索依赖语义相似性，能召回同义改写、跨语言表述和隐含关联的段落。两者失败模式互补，因此融合几乎总能提升召回。

## BM25 与稀疏通道

BM25+ 在经典 BM25 上增加了一个常数项 delta，避免长文档中低词频查询词的得分被过度压制。稀疏通道的关键参数是 k1（词频饱和度）与 b（文档长度归一化强度）。对中文语料，分词策略比算法本身更关键：中文没有空格边界，使用字符二元组（bigram）索引通常比单字索引显著更稳，因为单字噪声大、区分度低。

## 稠密通道与 ANN

稠密通道把查询和文档映射到同一向量空间，用余弦相似度排序。当语料规模变大时，精确检索代价过高，需要近似最近邻索引：HNSW 用多层可导航小世界图做贪心搜索，IVF 先聚类再只扫描最近的若干簇，PQ/SQ 量化则通过压缩向量降低内存与带宽开销。小规模语料直接用批量矩阵乘法做精确检索反而更快、更可控。

## Reciprocal Rank Fusion

RRF 是当前最常用、最稳健的融合方式。它只看每个通道内的排名，不看原始分数：score = sum(1 / (k + rank))，其中 k 通常取 60。RRF 的优点是无需分数校准，天然抗异常值，且对通道间量纲不一致完全免疫。缺点是丢失了分数强度信息，弱相关但排名靠前的文档可能被高估。

## 加权分数融合

加权融合先对每个通道的分数做 min-max 或 z-score 归一化，再按权重求和。它在通道分数可靠时更精确，可以显式表达"这个场景更信任词面匹配"。代价是需要校准：BM25 分数无上界、稠密余弦有界，两者直接相加会让 BM25 主导。生产上常见配置是 BM25 权重 1.0、稠密权重 1.0，再对重排通道附加 0.5 权重。

## 元数据过滤

现代检索几乎都带结构化过滤：时间范围、来源可信度、文档类型、租户隔离。过滤应在候选生成阶段生效，而不是在重排之后，否则 top-k 名额会被不合规文档占满，导致有效召回骤降。
