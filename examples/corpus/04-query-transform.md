# Query Transformation

用户问题往往不适合直接检索：太短、太口语、含指代、或隐含多个子问题。

## HyDE

Hypothetical Document Embeddings 先让 LLM 写一段"假设性答案段落"，再用这段段落的向量去检索。它把查询空间移动到与文档空间同分布，缓解了"短问题 vs 长文档"的表示不对称，在稠密通道上收益最大。风险是模型幻觉会把检索带偏，因此通常保留原始问题作为并行通道。

## Multi-Query

Multi-query 生成多个同义或不同侧重的改写，分别检索后合并去重。它直接扩大召回覆盖面，对表述多样的语料特别有效，代价是检索次数线性增加。

## Step-Back Prompting

Step-back 先把具体问题抽象成一个更一般的概念问题，检索背景知识，再结合原始问题作答。当问题依赖某个未被直接提及的原理时，抽象问题能召回原理性段落。

## 问题分解

复杂问题拆成若干原子子问题，分别检索、分别作答，最后综合。这是多跳问答的标准做法，也让证据引用可以追溯到具体子问题。

## 检索路由

路由器根据问题类型选择通道：事实型走稀疏、概念型走稠密、聚合型走摘要树、结构化数据走 SQL 或图查询。路由本身可以用规则实现，也可以用一次低成本 LLM 分类完成。
